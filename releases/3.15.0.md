## What this release is about

This release finishes the asset work started in 3.14.0, all requested in [#200](https://github.com/edmozley/freeitsm/issues/200). Every software, drive and device list on an asset now says which tool reported it, how old it is and whether the last attempt worked, and a failed collection keeps the last good list instead of wiping it. Assets can record what is **plugged into what**, from both ends. And the cases FreeITSM has always refused to guess about - two records with the same serial, a new laptop wearing an old one's name - now wait in a **review list**, where two records can be **merged** into one with nothing lost. Run Database Verification after upgrading.

## New features

- **How fresh is each list?** Above Storage, Devices and Software, a line says which tool reported the list and when it looked - *From the agent, observed 3 hr ago* - in amber once it is older than **Assets → Settings → Discovery & reconciliation → Inventory counts as stale after** (7 days unless you change it), and in red with the error when the last collection failed, showing how old the list it kept is. An **Inventory sources** panel on Key info lists every tool that reports the asset and every list it holds. A list nothing has ever reported says so, and its tab shows a dash instead of 0, so 0 now only means a tool looked and found none. See [Inventory freshness](https://github.com/edmozley/freeitsm/wiki/Inventory-Freshness).
- **Connected assets.** A **Connected** tab shows what is physically attached to an asset - a monitor on a computer, a phone in a dock - and it shows from both ends. Record one with **Connect**; tools that scan your network can report what they see through the REST API, shown as *last observed connected*. What a person confirmed and what a tool saw sit side by side and never overwrite each other, nothing is disconnected because a report forgot to mention it, and every connection is in both assets' history. It is not custody and not a service dependency. See [Connected assets](https://github.com/edmozley/freeitsm/wiki/Connected-Assets).
- **The review list.** **Assets → Settings → Review** shows two assets sharing a serial number, a new machine still wearing an old one's name, and devices a tool reported that match no asset - for you to **Merge**, mark **Different**, **Ignore**, or **Create** the device. Decisions stick, a case that sorts itself out closes on its own, and an asset in the list says so on its own page. See [Asset review](https://github.com/edmozley/freeitsm/wiki/Asset-Review).
- **Merging two assets, keeping everything.** Choose the record to keep, and everything on the other moves to it: history, tickets, contracts, documents, projects, leases, custody, connections, custom field values and inventory. Nothing is doubled, and empty fields are filled from the other record. Its printed QR label, links to it and tools reporting to it through the REST API all still find the one you kept. A merge cannot be undone and needs the *Discovery & reconciliation* permission.
- **Corrections that stick.** A padlock beside an asset's **Name**, **Manufacturer** and **Model** stops the agent and Intune overwriting it, and shows what they report instead (*The agent reports "HP"*) with **Release** to hand it back. Correcting one of these on an asset a tool reports protects it automatically - a setting, on by default.
- **One name per maker.** **Discovery & reconciliation → Manufacturer and model names** shows HP Inc. and Hewlett-Packard as HP in the table view, its filters, the asset search and dashboard charts, so a chart by manufacturer stops splitting one maker into three slices. Each asset keeps the value it reported.

## Improvements

- **The inventory agent says what happened to each list.** The agent script that ships with this release reports every list it collected - even an empty one - and names any it could not read, so FreeITSM can show *Reported empty* and *Failed*. Your existing script keeps working exactly as before, and the new one is safe against older FreeITSM versions, so roll it out whenever suits you. See [The inventory agent](https://github.com/edmozley/freeitsm/wiki/Inventory-Agent).
- **One way of saving inventory.** The agent and tools reporting through the REST API now save through the same code, so they can no longer drift apart, and a list that fails to save no longer leaves others half-written. This closes the last part of [#194](https://github.com/edmozley/freeitsm/issues/194).
- **REST API.** `GET /assets/{id}/inventory` says what each list's last attempt came to, a tool can report connections in its inventory report, and `GET /assets/{id}/connections` reads them. See [REST API: Assets](https://github.com/edmozley/freeitsm/wiki/REST-API-Assets).
- **The asset page's tabs no longer squeeze** onto two lines when there are more than fit; the row scrolls sideways instead.
- The screens new in 3.13.0, 3.14.0 and this release are in English in every other language for now, and will be translated in a later release.

## Fixes

- **Moving an asset to another company left its links to reporting tools behind.** A tool's next report in the old company could then refuse with a message naming the moved asset, and the new company could link the same device to a second asset. The links now move with the asset, and a move that would put the same device on two assets is refused with the reason.

## Upgrading

1. Pull the new code, or rebuild the Docker image.
2. Sign in as an administrator and run **System → Database Verification** - it adds the tables for connections, the review list, merges, protected values and name mappings, and records each list's last attempt.
3. Hard-refresh your browser (Ctrl-F5).
4. Optional: roll out the new `scripts/Invoke-AssetInventory.ps1` to your machines to see *Reported empty* and *Failed* from the agent. The old script keeps working.

## Rollback

Safe - nothing was removed from the database, so you can go back to 3.14.0. Any merges already made stay made.
