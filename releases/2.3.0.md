## What this release is about

**This release is about forms.** Until now a FreeITSM form was a list of questions down a page. It now lays out like a real document and asks the kinds of questions real paperwork asks.

**Questions can sit side by side**, so *Department* and *Date* share a line instead of taking two, and a label can sit beside its answer box the way a printed form reads. **Notes, warnings and images** can be placed among the questions — a rule somebody needs to read before they answer, a floor plan beside the question about which room. And a question can now be answered with **a table**: you define the columns once and whoever fills the form in adds as many rows as they need, which is what a purchase requisition or an equipment order has always actually been.

Two things make forms easier to live with. **Save draft** keeps a half-finished form and picks it back up later, for when the cost code is with finance and you are not getting it today. And a form in the self-service catalogue can be **restricted to one or more groups of people**, so a form meant for managers is only offered to managers.

Everything here is additive. No existing form changes shape, no setting has to be touched, and a form with no width, no restriction and no draft behaves exactly as it did.

Upgrading asks nothing of you beyond running Database Verification.

Rollback: safe — this release only adds to the database.

## New features

- **[Questions side by side](https://github.com/edmozley/freeitsm/wiki/Forms#laying-a-form-out).** Every question has a **Width** — full, three-quarters, two-thirds, half, third or quarter — and anything narrower shares its line with what follows. Twelfths rather than halves and thirds, so the uneven pairs a real document wants come free: *Department* deserves more room than *Date*, and that is two-thirds plus a third rather than half and half. Each question also has a **Label** setting, *Above* or *Beside*, so a row can read `First name [____]   Surname [____]`. Everything returns to one question per line, labels above, on a phone.

- **[Notes and warnings](https://github.com/edmozley/freeitsm/wiki/Forms#notes-warnings-and-images).** A **Note** sits among the questions and is simply read — "all purchases over £500 need director approval". It takes a one-line message, an optional paragraph, and a style: Plain, Information, Warning, Important or Success. You pick the *name* rather than a colour, so it reads correctly in light mode and in dark without you choosing twice. A note can be conditional, so a red warning appears only when somebody ticks the box that makes it relevant — which is worth about ten that sit on screen permanently.

- **[Images on a form](https://github.com/edmozley/freeitsm/wiki/Forms#notes-warnings-and-images).** A logo at the top, a floor plan beside the question about which room, a diagram of the thing being requested. Sized as a share of its column rather than in pixels, so it stays sensible on any screen, and full width again on a phone.

- **[Questions answered with a table](https://github.com/edmozley/freeitsm/wiki/Forms#table-questions).** One question, as many rows as the person needs — ITEM / DESCRIPTION / UNIT / QUANTITY running down the page. You set the columns up once; each is text, number, dropdown, choose-one, tick box or date. Columns can be renamed, reordered and retired without breaking answers people have already given: a retired column still labels its old answers on the submissions that used it. The answers come back as a real table on the submission, in the PDF and in a collection, and the CSV gets one column per table column.

- **[Save draft](https://github.com/edmozley/freeitsm/wiki/Forms#drafts).** A button beside Submit, on the analyst side and in the self-service portal. It keeps what you have typed and leaves the form unsent; open the form again and it is all still there, with a note of when you saved it. Nothing is checked when you save — required questions can be empty, because not being finished is the point. A draft is yours alone: it is not a submission, so it appears in no list, no export and no approval queue, and it raises nothing.

- **[Offer a form to some customers and not others](https://github.com/edmozley/freeitsm/wiki/Forms#who-can-request-a-form).** Asked for in [#145](https://github.com/edmozley/freeitsm/issues/145). A **Who can request this form** button on the Forms list restricts a catalogue form to one or more groups, using the groups you already keep in **Tickets → Users → Groups**. By default every form is open to everyone, and it stays that way unless you say otherwise. A customer outside the groups does not see the form in their catalogue, cannot open it from a link somebody sends them, and cannot submit it.

## Improvements

- **The Forms help guide is now several pages instead of one.** It was the longest guide in the product before this release added six more areas to it. The guide keeps the basics and links to five in-depth pages — laying a form out, notes and images, table questions, drafts, and who can request a form — each with its own contents list.

- **The builder's Preview tab shows your layout.** It was ignoring field widths entirely, so you set two questions to share a line, clicked Preview, and saw them stacked. The one screen whose job is showing you what you have built is now the one that does.

- **A lookup field is no longer invisible in the Preview tab**, and its badge in the builder reads *Lookup* rather than the word `forms.typename.lookup`.

- **Restrictions are checked everywhere, not just on the catalogue page.** A form hidden from a customer's catalogue also cannot be opened by id, drafted, have its images fetched, or submitted. A hidden card has never been a check, and a link shared between colleagues should not become a way in.

## Fixes

- **The CSV export put answers under the wrong headings.** Any form with a lookup question exported a row one cell short, so every column after that lookup lined up beneath its neighbour's heading — in every export, with no error to tell you. If you have exported a form with a lookup question, the file is wrong and worth taking again.

- **A table question showed its headings beside its boxes instead of above them**, reported within minutes of the first one being built.

- **The self-service portal showed customers a raw label.** A form with a lookup question rendered its search box with the placeholder `forms.fill.lookup_placeholder` — the internal name of the text rather than the text — in every language.

## Upgrading

1. Pull the new code, or rebuild the Docker image.
2. Sign in as an administrator and run **System → Database Verification**. This release adds two tables — one for drafts, one for who can request a form — and one column to the forms table.
3. Hard-refresh your browser (Ctrl-F5).

Nothing else to set, and nothing to switch on. Every new setting is off, empty or absent by default.

## Rollback

Safe. This release only adds to the database — nothing was removed or changed in place, so you can go back to 2.2.0. Drafts and form restrictions saved in 2.3.0 would simply stop being read.
