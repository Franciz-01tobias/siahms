## What this release is about

**Includes a security fix for installs with more than one company** - repeating tasks did not check which company a task belonged to (below). If you run several companies, upgrade.

You can now **make up your own ticket fields** - a start date, a username and "remote worker?" on a new starter, say - link them to the ticket types that need them, and decide for each one whether it must be filled in when the ticket is logged, before it is closed, or both. Requesters can be asked for them on the portal. Anyone who would rather see their modules than open the waffle menu can switch on a **sidebar** of module icons. On a desktop the **ticket reading pane** is denser, so the conversation starts much higher up the screen. Run Database Verification after upgrading: it adds four tables.

## Security

- **Repeating tasks ignored company scope.** On an install with **more than one company**, an analyst with Tasks access in one company could set up, change or stop a repeat on another company's task, or read that task's title through the repeat preview or the calendar's future occurrences, by sending a task number they were not allowed to see. Every other part of Tasks already checked. Present in every release from **1.0.0 to 3.9.0**. A single-company install was never affected, and nothing was exposed to the portal or to anybody without Tasks access. Nothing to do beyond upgrading; if you want to be sure nothing was changed, look over the repeating tasks you rely on and confirm each is still set to repeat. [Write-up](https://github.com/edmozley/freeitsm/wiki/Repeating-Tasks-Ignored-Company-Scope).

## New features

- **Custom ticket fields.** **Tickets → Settings → Custom fields** creates fields of your own - text, a number with an optional unit, a date / time / date and time, yes / no, a dropdown of your own options, a web address or an email address - and links each to some ticket types or to all of them. Each field chooses whether it must be filled in **when the ticket is logged** (the New ticket form, the REST API and, when asked, the portal), **before the ticket is closed** (following your Mandatory fields setting: warn, warn and email, or refuse), or both. The fields sit in the ticket's properties panel beside the built-in ones, save as you change them and appear in the ticket history. Changing a ticket's type hides the answers its new type does not have, and never deletes them. Requested in [discussion #179](https://github.com/edmozley/freeitsm/discussions/179). See [Custom ticket fields](https://github.com/edmozley/freeitsm/wiki/Custom-Ticket-Fields).
- **Asking the requester on the portal.** Tick **Ask the requester on the portal** on a custom field and it appears on the portal's New ticket form. Once a field belongs to particular types, the portal also asks **"What kind of request is it?"**, so a requester choosing New starter is asked the New starter questions. Fields only your team should fill in are never shown to requesters.
- **An optional sidebar.** **Preferences → Display → Sidebar** puts a rail of module icons down the left of every screen. Tick the modules you want on it - only ones you can open are offered - and it follows your own module order. Its **Recent** button opens your recent trail, and a shortcut at the bottom brings you back to its settings. It is off until you switch it on, the waffle menu stays where it is, and a phone keeps its compact menu. Requested in [discussion #124](https://github.com/edmozley/freeitsm/discussions/124). See [The sidebar](https://github.com/edmozley/freeitsm/wiki/App-Sidebar).

## Improvements

- **More room for the conversation on a ticket.** On a desktop the header above the thread is denser: a smaller subject, **From, To and Date on one line**, the **Links and AI summary side by side**, and the actions on **one row** - with **Audit, Write up, Feedback and Delete under ⋯ More**. Scroll down the thread and the header **shrinks to the subject alone**, and comes back when you scroll to the top. The "no checklist attached" box now only appears when there is a checklist attached or suggested.
- **New is in the same place in Tickets, Assets and Software** - a **New** button at the right of a strip under the module's menu bar. Assets' table view, which had no way to add an asset, has one too. This is the first step towards the same place in every module; see [UI style guide](https://github.com/edmozley/freeitsm/wiki/UI-Style-Guide) and [discussion #185](https://github.com/edmozley/freeitsm/discussions/185).
- **"Read it for me" is now "Read it".**

## Fixes

- **A mailbox import was logged as "success" with no ticket**, and two analysts with the inbox open could, at worst, turn one email into two tickets. Every open inbox checked every mailbox each minute on its own timer, so two checks sometimes picked up the same email. Now only one check of a mailbox runs at a time, open inboxes share one automatic check a minute between them, and an email that was already imported is logged as **Already imported** with the ticket it went to. Nothing had been lost. Reported in [#183](https://github.com/edmozley/freeitsm/issues/183); [write-up](https://github.com/edmozley/freeitsm/wiki/Mailbox-Checks-Overlapped).
- **A mailbox's "Never checked" and "Not checked for N days" warnings blamed a scheduled task** that does not exist. Mail is collected while somebody has the ticket inbox open, and the warnings now say so.

## Upgrading

1. Pull the new code, or rebuild the Docker image.
2. Sign in as an administrator and run **System → Database Verification**. It adds four tables for custom ticket fields.
3. Hard-refresh your browser (Ctrl-F5).

Designing custom fields is its own permission, **Custom fields** under Tickets in **System → Roles**. Administrators have it already; give it to anybody else who should design them.

## Rollback

Safe - this release only adds to the database, so you can go back to 3.9.0.
