## What this release is about

A small security release, the same day as 3.8.0. Checking the 3.8.0 fix for change text turned up a few more places in Change Management that showed setting names - statuses, types, priorities and impact levels - without making them safe first. Nothing else changes, so it is a quick upgrade.

## Security

- **Change Management setting names could run script.** The status, type and priority badges in the change list, the impact level on an open change, and the status filter on the change calendar showed those names exactly as saved. Somebody allowed to edit Change Management's settings could therefore name a status so that it ran script for everybody who used Change Management. The names are now always shown as plain text. Only people with permission to change Change Management settings could do this. Present in 1.0.0 to 3.8.0. Nothing to do beyond upgrading.

## Fixes

- **A status with an apostrophe in its name broke the change calendar's status filter** - ticking it did nothing.

## Upgrading

1. Pull the new code, or rebuild the Docker image.
2. Sign in as an administrator and run **System → Database Verification**.
3. Hard-refresh your browser (Ctrl-F5) - this release updates cached JavaScript.

## Rollback

Safe - nothing was changed in the database, so you can go back to 3.8.0 with the code alone.
