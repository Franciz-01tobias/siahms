## What this release is about

Tickets get two new ways to work: a workspace that lays one ticket out for working rather than reading, and a ticket table you can filter, sort and export. An administrator can now switch off whole modules, and some Tickets features, for the whole installation, so a team that doesn't use them never sees them. Catalogue requests can be approved by a team, with a set number of different members agreeing. Most of this release came from @Dr4inder, who wrote the workspace and the ticket table and asked for the rest - thank you.

## New features

- **The ticket workspace.** An optional layout with the ticket's properties in a column on the left, and its conversation, work, links, time and history on tabs. Linked tasks open their own editor right there, and a ticket's checklist lists every step. Switch it on in Tickets → Settings → General → Ticket workspace: off (the default), for chosen tickets only (More → Make workspace), or for every ticket. Each analyst can still turn it off for themselves. Contributed by @Dr4inder ([#211](https://github.com/edmozley/freeitsm/pull/211), [#212](https://github.com/edmozley/freeitsm/pull/212)).
- **The ticket table.** Choose Table instead of Messages at the top of Tickets to see the list as a table with column filters and saved views. Clicking, right-clicking, dragging to folders and the bulk actions all work as they do in the message list. The CSV export takes every matching ticket, and Tickets → Settings → General decides who may use it. Contributed by @Dr4inder ([#213](https://github.com/edmozley/freeitsm/pull/213)).
- **Switch modules off for the whole installation.** System → Modules → Availability. A module that is switched off disappears for everyone, from menus, other modules' screens, the portal, the REST API, workflows and scheduled jobs. Nothing is deleted, and switching it back on restores everything. CSAT, SLA, time tracking and the duty rota can be switched off the same way. Upgrading switches nothing off. Requested by @Dr4inder ([#217](https://github.com/edmozley/freeitsm/issues/217)). Details: [Switching modules off](https://github.com/edmozley/freeitsm/wiki/Switching-Modules-Off).
- **Catalogue approval by a team.** A catalogue form's approval settings can now choose a team instead of one person, and say how many different members must approve, and how many rejections decline it. The person who made the request never votes on it. An administrator can override, or move a stuck request to someone else, always with a reason that is recorded on it. Forms with a named approver work exactly as before, and a named approver can now be barred from approving their own requests. Requested by @Dr4inder ([#220](https://github.com/edmozley/freeitsm/issues/220)). Details: [Catalogue Request Approvals](https://github.com/edmozley/freeitsm/wiki/Catalogue-Request-Approvals#approval-by-a-team-430).

## Improvements

- **The Tasks table can open a task.** Each row has an open icon, and Open is on the right-click menu, showing the same panel as the Calendar and Timeline without losing your place. Preferences → Opening a task chooses between a quick look and the full task, with subtasks, checklists and comments ([#219](https://github.com/edmozley/freeitsm/issues/219)).
- **The Links bar on a ticket stays on one line.** Long names are shortened, and links that don't fit fold into a "+N" button.
- **The workspace's Work tab says how to add a checklist or task** when a ticket has none.

## Fixes

- **A workflow's "Send an email" failed with an access-token error** when it sent from a chosen Microsoft mailbox ([#216](https://github.com/edmozley/freeitsm/issues/216)). Thanks to @Abdullah31H. A workflow's "Create a ticket" now also sets the Owner, and gives the ticket a mailbox so replies to it can be emailed.
- **The "contains" and "does not contain" workflow conditions were case-sensitive**, so "abc.com" did not match User@ABC.com ([#214](https://github.com/edmozley/freeitsm/issues/214)). Thanks to @duongtuanan. They now ignore capitals and any spaces around what you type.
- **Searching tickets for "we're" missed subjects written with a curly apostrophe**, as Gmail and Outlook send them.
- **The More menu on a ticket could open off the edge of the reading pane** on a narrow window.
- **The selected row in the ticket table was unreadable in dark mode.**

## Upgrading

1. Pull the new code, or rebuild the Docker image.
2. Sign in as an administrator and run **System → Database Verification**. It adds the tables and columns for team approvals and the ticket workspace.
3. Hard-refresh your browser (Ctrl-F5). This release updates cached scripts on the Tickets, Tasks and Forms pages.

Things to know:

- The workspace is off until an administrator switches it on, and every module stays on until someone switches it off.
- The new screens are in English for now in other languages; translations follow.

## Rollback

Safe. This release only adds to the database, so you can go back to 4.2.0.
