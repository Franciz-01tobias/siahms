## What this release is about

A small fix release for Projects. Since 3.3.0, pressing Save when adding or editing a phase on a project's plan did nothing, and announcing disruption from a project ignored the title you typed. Both are fixed. The tasks and projects demo data also imports again on databases that refuse it, such as MariaDB and the database in the Docker setup. Nothing else changes.

**Fixes a problem present in 3.3.0, 3.4.0 and 3.5.0** - phases could not be added to a project. If you use Projects, upgrade.

## Fixes

- **Adding or editing a phase did nothing on Save.** On a project's Plan tab, Save and Enter in the phase dialog now save the phase. Thanks to @LvNixia, who reported this in [#175](https://github.com/edmozley/freeitsm/issues/175) and pinned down the cause exactly. [The full write-up](https://github.com/edmozley/freeitsm/wiki/Projects-Phase-Save-Did-Nothing) explains what was wrong.
- **Announce disruption ignored its title.** Announcing disruption from a project kept answering "Give the maintenance a title." even when one was typed. It now uses the title you typed.
- **The tasks and projects demo data would not import on some databases.** The import stopped with "Data too long for column 'reason'" on MariaDB and on MySQL in strict mode, which includes the database in the Docker setup. It now imports everywhere.

Nothing wrong was saved while these bugs were live, so there is nothing to clean up.

## Upgrading

1. Pull the new code, or rebuild the Docker image.
2. Sign in as an administrator and run **System → Database Verification**.
3. Hard-refresh your browser (Ctrl-F5) - this release updates cached JavaScript, and an old copy will make it look as if Save still does nothing.

## Rollback

Safe - nothing was changed in the database, so you can go back to 3.5.0 with the code alone.
