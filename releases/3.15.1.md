## What this release is about

**Upgrade this one promptly.** It is a security release and nothing else: the fixes from two private security reports, present in every release up to and including 3.15.0. The most urgent two: on the shipped settings, the lockout after five wrong passwords did nothing all summer, so passwords could be guessed without limit; and a link on another website could make a signed-in analyst empty the ticket trash or change settings. Nothing new to learn. Upgrade and carry on.

## Security

- **Signing in.** All summer, on the shipped settings, the account lockout lifted the moment it was set, so a password could be guessed without limit (a time stored in UTC was read back in local time). Another website could also sign a visitor in as somebody else. The forced change of the default `admin` password accepted the default. And errors before sign-in could show server details. All four are fixed, and every place that sets a password now refuses short, published and very common passwords. A full write-up will follow.
- **A link could change data.** About twenty actions, from emptying the ticket trash to switching module permissions to "most", wiping the SLA settings or importing the demo data, could be triggered by a link that a signed-in analyst clicked. Every action that changes data now refuses one, and an automated check stops a new one being added. Details: [A link could change data](https://github.com/edmozley/freeitsm/wiki/A-Link-Could-Change-Data).
- **Knowledge articles could run scripts.** An article body posted around the editor ran in the browser of every analyst who opened it, administrators included. Bodies are now cleaned before they are shown, and embedded videos keep working. Separately, an analyst who had been denied an article could still edit, move, archive or delete it. Details: [Knowledge articles could run scripts](https://github.com/edmozley/freeitsm/wiki/Knowledge-Articles-Could-Run-Scripts) and [Knowledge writes ignored permissions](https://github.com/edmozley/freeitsm/wiki/Knowledge-Writes-Ignored-Permissions).
- **Access outlived its removal.** A demoted administrator, an analyst who lost a module, or a deactivated analyst kept some of that access until they signed out, and a deactivated analyst's calendar links and Watchtower key kept working. Everything is now checked at the moment of use, including sessions and links that already exist. Details: [Access outlived its removal](https://github.com/edmozley/freeitsm/wiki/Access-Outlived-Its-Removal).
- **Company boundaries** (multi-company installs). A company-limited API key could reach another company's requesters. A moved ticket stayed in the old company's search and left its tasks behind. Workflow-raised tickets landed in triage. An analyst with no company access saw the Default company. Watchtower counted every company. Details: [Company boundaries](https://github.com/edmozley/freeitsm/wiki/Company-Boundaries-October-2026).
- **Mailbox sign-in is checked properly.** Connecting a Microsoft 365 or Gmail mailbox now confirms the sign-in was started from FreeITSM, by the analyst who finishes it. A full write-up will follow.
- **Smaller gaps.** Software inventory API keys were readable without their permission. The portal's privacy setting could be beaten by a similar email address, and its ticket list previewed mail the setting hides. Ticket history, including the rows SLA timing reads, could be written freely. Webhook secrets were stored readable when saved through the API or a form. A workflow could raise a ticket for a request still awaiting approval. Portal recordings skipped the upload checks. One debug tool needed no sign-in. Details: [Smaller gaps](https://github.com/edmozley/freeitsm/wiki/Smaller-Gaps-October-2026).

These were reported privately by a security researcher, who asked not to be named. Thank you.

## Upgrading

1. Pull the new code, or rebuild the Docker image.
2. Sign in as an administrator and run **System → Database Verification**. This release changes nothing in the database, but run it anyway.
3. Hard-refresh your browser (Ctrl-F5). This release updates cached scripts.

Things that now behave differently, in case they affect you:

- **Passwords** must be at least 8 characters and not a published or very common one, wherever they are set, including when an administrator creates an analyst.
- **Errors are no longer shown on screen** on a manual or WAMP install (Docker never showed them). To see them on a development machine, add `define('FREEITSM_DISPLAY_ERRORS', true);` to `db_config.php`.
- **The Watchtower browser extension** needs a key generated by an analyst who has Watchtower. A software inventory agent's key no longer opens it.
- **Your own scripts** that call FreeITSM's internal endpoints (not the REST API under `/api/v1/`) and save something with a `GET` will now get an error and must use `POST`.

## Rollback

Safe. Nothing was removed from the database, so you can go back to 3.15.0, but going back reopens every issue above.
