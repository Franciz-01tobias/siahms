## What this release is about

**This release closes a security hole that is present in every version up to and including 2.3.0, so please upgrade.** The developer test scripts that ship in the `tests/` folder were reachable over the web on a normal install, and running one needed no sign-in. Nothing about upgrading asks anything of you beyond the usual steps, and rollback is safe.

The rest is the table question - the field type added in 2.3.0 that lets somebody fill in rows of data, like a purchase list. Three separate faults meant a table could look fine while you filled it in and then not survive being read back: a single-select column let you tick every option at once, the answers were missing from a submitted form's PDF, and a request containing a table broke the approvals inbox outright. All three are fixed, and no data was lost by any of them.

Forms are also noticeably wider now, and a form finally looks the same to a customer on the portal as it does to an analyst.

## Security

**The developer test scripts were reachable over HTTP, and running one required no sign-in.** This affects every release up to and including 2.3.0.

FreeITSM is installed by putting its folder in your web root, so the `tests/` folder went with it - including in the official Docker image. Most of those scripts exercise the real code against your real database: they create forms, assets, documents and working analyst accounts, and tidy up after themselves only when they run to the end. Over the web that made them unauthenticated write endpoints that anybody could trigger, and that a cut-off request could leave half finished. One leftover file displayed the email thread of a single ticket, addresses and message bodies included, with no permission check at all; it has been deleted.

**Upgrading is all that is required.** Afterwards, requesting anything under `/tests/` returns "not found". Three separate defences now do that: every script refuses to run unless it is started from a command line, the folder is denied at the web server for Apache and IIS, and the folder is left out of the Docker image entirely and blocked in the nginx configuration FreeITSM ships. If you cannot upgrade immediately, denying `/tests/` at your web server is a complete stop-gap.

I have no reason to think this was used against anyone, and there is no sign of it in anything reported to me. It was found by asking whether that folder belonged in the release at all, rather than by anybody exploiting it.

## Improvements

- **Forms are wider, and the portal now matches the analyst view.** A form was capped at one width when an analyst filled it in and a narrower one on the self-service portal, so the same form was about a sixth narrower for the customer it was written for. Both are now the same, and both are wider than either used to be. This matters most for the narrow field widths: a quarter-width field was previously too tight to hold a date box comfortably once its label was translated into a longer language.

## Fixes

- **The approvals inbox showed "Error" instead of the requests waiting to be approved.** It happened as soon as any waiting request contained a table question, for every analyst including administrators, and the tab counts stayed correct while the list itself failed - which made it look as though the whole screen was broken rather than one answer in one request. The same fault also reached the approval notification email and workflow merge codes, where a table appeared as the word "Array" rather than its contents. Reported with screenshots by a user; thank you.

- **A submitted form's PDF showed a table question's heading with nothing underneath it.** The answers were never lost - the record kept them all along, and they reappear as soon as you upgrade. The on-screen record and the CSV export were missing the same rows for the same reason, so it is worth re-checking any submission you looked at and assumed had been left blank.

- **A single-select column in a table let you tick every option at once.** Choosing 1, then 3, then 5 added a filled circle each time instead of moving it. It affected both the analyst form and the self-service portal. **Worth knowing when you read older records:** a submission saved while this was happening kept only the *first* option ticked in each cell, so an answer may be missing a later choice. There is nothing to repair and nothing you need to do, but an old answer may be incomplete.

- **A form built with fields side by side drew as one long column on the self-service portal.** Every width an author set was ignored there, while the same form laid out correctly for analysts. Reported by a user who noticed the two did not match.

- **The Tasks board stopped responding to clicks after you closed a task**, if you were using the large-window view, until you reloaded the page. It was reported as a problem with deleting a task, but it happened on any close - the X, the overlay or the Escape key - because the closed window was still lying invisibly across the board and quietly taking every click.

## Upgrading

1. Pull the new code, or rebuild the Docker image.
2. Sign in as an administrator and run **System → Database Verification**.
3. Hard-refresh your browser (Ctrl-F5) - this release updates cached stylesheets, and a stale one will make forms look unchanged.

Nothing else is needed. There is no new setting, no new environment variable and nothing to configure.

## Rollback

Safe - this release only adds to the database, so you can go back to 2.3.0 if you need to. Note that going back also reopens the security issue above.
