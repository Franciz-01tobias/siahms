## What this release is about

**Includes two security fixes** (below): one for installs with more than one company, and one that matters to everybody who uses Tasks. Upgrade.

This release is about **proving that routine work was done**. A repeating task now keeps a complete history and has an **evidence report** - every occurrence, whether it was on time, skipped (with the reason) or missed, and what its checklist recorded. A task can **need forms and Knowledge procedures**, filled in from one **Work view** with a single Complete button. Every **background job** now records its runs, so you can see at a glance - and have a monitor told - when one has stopped. Any AI feature can use a **self-hosted model**, and the REST API gains custom asset fields, change evidence and inventory reports from your own tools. Run Database Verification after upgrading.

## Security

- **A task's description could run code in the browser of whoever opened it.** A task's description is formatted text, and it was shown in the task window and the Calendar and Timeline quick panels without being cleaned. Text crafted to include a script ran when another person opened the task, with their access. Who could write it: anybody who can edit tasks, or a REST API key that can; and, **if you have a workflow that copies a ticket's subject or body into a new task's description**, whoever raised that ticket - by email or on the portal. Descriptions are now cleaned the same way email bodies are, keeping formatting and pasted pictures. Present in every release from **1.0.0 to 3.11.0**. Nothing to do beyond upgrading; if you have such a workflow and want to be sure, look over tasks it created for anything you did not expect. [Write-up](https://github.com/edmozley/freeitsm/wiki/Task-Descriptions-Were-Not-Cleaned).
- **A task's attached documents ignored company scope.** On an install with **more than one company**, an analyst with Tasks access could open, download or find through search the documents attached to another company's tasks. Every other part of Tasks already checked. Present in every release from **1.0.0 to 3.11.0**. A single-company install was never affected, and nothing was exposed to the portal or to anybody without Tasks access. Nothing to do beyond upgrading. [Write-up](https://github.com/edmozley/freeitsm/wiki/Task-Documents-Ignored-Company-Scope).

## New features

- **A task keeps its history.** A **History** tab in the task window shows everything that happened to it - created, assigned, moved, rescheduled, completed, reopened, its checklist ticked - by whom and when. It is written together with the change itself, so if the history cannot be saved, the change is not made either.
- **The evidence report for a repeating task.** **Repeats → Execution history**, or the new **Tasks → Evidence** list, shows every occurrence a repeat should have produced: **on time**, **on time after rescheduling**, **late**, **open**, **skipped** with its reason, **removed**, or **missing** - with flags for anything rescheduled or changed after completion, the checklist results and form answers, and what the scheduler was doing at the time. Print it to PDF, or export it as CSV files. See [Repeating task evidence](https://github.com/edmozley/freeitsm/wiki/Repeating-Task-Evidence). Requested in [#181](https://github.com/edmozley/freeitsm/issues/181).
- **Skip an occurrence, with a reason** - for the week the server being checked was being replaced. It shows as skipped, not missed.
- **Pass, Fail and Not applicable on checklist steps.** A step can ask for a result instead of a tick, and a failed step can be treated as an exception in the report.
- **Read only access to Tasks** - for an auditor who should see everything and change nothing - and **Tasks → Settings → Evidence**, which decides whether a completed task's checklist can still be changed, whether an occurrence may be deleted, and who may run the report.
- **Forms on tasks.** A task, or every occurrence of a repeat, can **need forms** from the Forms module - a weekly backup check, a site inspection. Drafts are shared, so a colleague can pick up where you left off, and two people cannot overwrite each other without being told. A task with an unfinished required form cannot be completed. A choice in a form can count as an **exception** in the evidence. See [Forms on tasks](https://github.com/edmozley/freeitsm/wiki/Forms-on-Tasks). Requested in [#190](https://github.com/edmozley/freeitsm/issues/190).
- **The Work view.** One place in the task window with the day the check is for, the **Knowledge procedures** to follow (the version used is kept for the record), the checklists and the forms, progress across all of them, and one **Complete** button. From a failed step you can **raise a follow-up** task or ticket, and a setting decides whether open follow-ups stop completion.
- **Background job health.** Every background job - SLA checks, mailbox and tracker polling, scheduled workflows, repeating tasks and the rest - now records its runs. **Reporting → System logs → Background jobs** shows each job as healthy, overdue, failing, partly failing, stuck, or never seen, with its run history; a **Watchtower card** and a notice on the System page appear while any job needs attention. A monitoring tool can call `GET /api/v1/jobs/health`, and with `?strict=1` it answers 503 while something is wrong. A job whose state cannot be read is shown as **Unknown**, never as fine. See [Background jobs](https://github.com/edmozley/freeitsm/wiki/Background-Jobs). Requested in [#182](https://github.com/edmozley/freeitsm/issues/182).
- **Self-hosted AI.** Every AI feature can use **OpenAI-compatible** servers - Ollama, LM Studio, vLLM, LocalAI or your own gateway - by entering its address and model name. Nothing has to leave your network. See [AI providers](https://github.com/edmozley/freeitsm/wiki/AI-Providers). Requested in [#192](https://github.com/edmozley/freeitsm/issues/192).
- **Task board cards sorted by due date.** **Card order** in the left panel switches between your own manual order and soonest due first. Requested in [#191](https://github.com/edmozley/freeitsm/issues/191).
- **More of the REST API** ([#194](https://github.com/edmozley/freeitsm/issues/194), all three contributed by [@Dr4inder](https://github.com/Dr4inder)):
  - **Custom asset fields** can be set when creating or updating an asset, saved together with the rest of the change; keys that were not used are listed in the response rather than silently ignored.
  - **Evidence on a change**: a deployment pipeline can attach its report to the change it implemented, with a key that can do nothing else. A retried upload is never stored twice.
  - **Inventory from your own tools**: an RMM, Lansweeper or a CMDB export can report the software, volumes and network adapters it sees on an asset. Its rows sit beside the agent's and Intune's, labelled with their source, never touch another source's rows, and never make an old scan look like a fresh check-in.
  - **A task's forms** can be read and submitted.

## Improvements

- **Task notifications say what happened** - a status or due date change, a comment, being added to or taken off a task - instead of a bare notice.
- **The same application can be recorded on a machine by two sources** - the agent and Intune, for example. Before, the second one was refused.
- **The Background jobs tables become cards on a phone.**
- **System → Contributors** credits [@Dr4inder](https://github.com/Dr4inder), and the project now has a [contributing guide](https://github.com/edmozley/freeitsm/wiki/Contributing) for anyone sending code.

## Fixes

- **Dragging a repeating task into a closed column never created the next one** for a repeat set to "after completion" - only ticking it complete did.
- **Repeats** could make a second next occurrence when one was reopened and completed again, counted "today" in UTC rather than your time zone, and could recreate an occurrence on a fixed schedule. All four fixed.
- **Background jobs that failed quietly now say so** - scheduled workflows and the SLA check no longer report success over a failure.
- **The training reminders web address could never work**; its token was never created.
- **A refused delete in the task window said nothing**; it now says why.
- **The REST API documentation said tasks were install-wide**; they are limited to the key's companies, as they have been for a while.

New screens and messages in this release are in English in every language for now; the translations follow in a later release.

## Upgrading

1. Pull the new code, or rebuild the Docker image.
2. Sign in as an administrator and run **System → Database Verification**. It adds tables for task history, forms and procedures on tasks, background job runs and REST inventory, and widens the software inventory's uniqueness rule, keeping every row.
3. Hard-refresh your browser (Ctrl-F5).

New permissions, in **System → Roles**: **View background job health** (Reporting), **Run the evidence report** (Tasks - only used if Tasks → Settings → Evidence says the report is limited) and **Read the form answers on tasks you can see** (Tasks). Administrators have them already. An auditor is **Read only** access to Tasks plus Run the evidence report.

## Rollback

Safe - this release only adds to the database, so you can go back to 3.11.0. Task history, job runs and inventory reported through the API stay in their new tables and are simply not shown.
