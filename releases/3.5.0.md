## What this release is about

This release adds **lease management** to Assets: keep your lease agreements, see which machines have to go back and when, and know who has them. **Single sign-on can now read the groups your identity provider sends**, so staff access is managed in Microsoft Entra, Okta or Keycloak and FreeITSM follows it - proved against a real Microsoft Entra tenant, and backed by a step-by-step setup guide. **Contracts and RFPs now belong to a company**, which lets assets, contracts and people be charged to cost centres. It also closes two gaps where someone who had left could still get in. Nothing breaks; run Database Verification after upgrading.

## Security

- **A requester marked as left could still sign in to the self-service portal**, with their password or through single sign-on, and an open portal session carried on. Every way into the portal now refuses them, and anyone already signed in is signed out on their next page. Present since 1.0.0.
- **A deactivated analyst kept working until they signed out.** Deactivating stopped new sign-ins, but an open session kept every module - and an administrator kept System. A deactivated analyst now loses everything on their next click. Present since 1.0.0.

Nothing to do beyond upgrading. If you have relied on a leaver still being able to sign in to read an old ticket, reactivate them.

## New features

- **Leases.** A new **Leases** button in Assets holds your lease agreements - leasing company, agreement number, cost centre, notice period, documents and an optional contract - split into schedules for kit leased at different times, each with its own dates and cost. Put assets on a schedule and their lease dates follow it; keep one laptop longer and it gets its own dates without touching the rest. Record what became of each asset (on lease, extended, returned, bought out - your own list, in **Assets → Settings → Leasing**). **Due back** lists everything still out whose lease ends soon, with who has it and where it is, and exports it to a spreadsheet. The calendar can show the last day to give notice.
- **Groups and teams from single sign-on.** An OpenID Connect provider (**System → SSO**) can read the groups your identity provider sends: an **analyst group** decides who may sign in as an analyst, an **administrator group** who is an administrator, and each group can put people in a FreeITSM **team** - which gives them that team's modules, companies and roles. It is checked at every sign-in, so adding someone to a group gives them access and removing them takes it away. Everything is chosen from dropdowns of the groups your provider has actually sent, and groups that arrive as codes (Microsoft Entra) can be given names. A step-by-step guide with a checklist for Entra, Okta and Keycloak is linked from the screen.
- **Contracts and RFPs belong to a company.** Each contract and each RFP now has a **Company**, separate from who the contract is with. Lists follow the company switcher, and contract numbers only need to be unique within a company.
- **Cost centres on assets, contracts and people.** Each can be charged to one of its company's cost centres - on the record, in the asset spreadsheet import by code, and through the API. Assets → Table has a Cost centre column. A contract's old typed-in cost centre is linked automatically where it matches a code.
- **Create analysts and set their access through the API.** An HR system or identity provider can create analysts, keep their details in step, set their modules, companies, settings permissions and administrator flag, and deactivate them when they leave. Only an API key that acts as an administrator for all companies can make changes. Designed by @Kraleemil.
- **Attachment size limits you choose.** **System → Security → Attachments** sets the largest attachment (it was fixed at 10 MB) and the largest email. **Tickets → Settings → Mailboxes** decides what happens to an email that is too big: keep it without the oversized files, or reject it - with an optional alert and a reply to the sender, and different rules per mailbox if you want them.
- **A link back to your own site.** **System → Branding** can show a small *Back to the intranet* link at the top of the portal, the analyst screens or both.

## Improvements

- **The System screen's search finds settings inside each area** - type *name* and it shows Branding, with a link straight to the System name setting.
- **Page titles read the same everywhere:** *your system name - module - page*. The system name moved to **System → Branding**.
- **Assets:** a **Lease starts** date beside Lease ends (both are also columns in Assets → Table, the import and the API), a **Financial** tab on each asset for the money fields so Key info is about the machine, and slightly narrower navigation buttons so everything fits.
- **Single sign-on and LDAP providers choose which companies an analyst they create can see** - every company (as before), only the provider's own company, or none.
- **The single sign-on provider window is now large, with tabs**, instead of one long form.
- **System → Roles** shows the settings permissions set through the API for one person, marked API and read-only.
- **The API can mark a requester as left**, and requesters read back with whether they are active.
- **AI connections are easier to diagnose.** Azure accepts the address you paste from the portal; a failing test explains the likely cause; and debug tool **D014** now shows the full request and answer for every provider.
- **Group names match whatever their capitalisation in any alphabet**, for single sign-on and LDAP alike - "Équipe-IT" and "équipe-it" are now the same group.

## Fixes

- **The portal's "Analyst console" link reopened the portal** on installs whose front door is the portal (#169).
- **On a multi-company install, the portal's New Ticket form offered every company's mailboxes** (#172). It now offers the requester's own company's and shared ones.
- **Newer AI models (gpt-5 and similar) failed every request**, because they only accept their default temperature (#171).

## Upgrading

1. Pull the new code, or rebuild the Docker image.
2. Sign in as an administrator and run **System → Database Verification**. It adds the lease tables, the single sign-on group tables, a company on contracts and RFPs, cost centre columns, and a few others.
3. Hard-refresh your browser (Ctrl-F5).

Things worth knowing:

- **Existing contracts** are filed under the Default company, and a contract with a customer under that customer's company, so nobody's view changes on upgrade. The old setting that made customer contracts visible to everyone has gone - visibility now follows each contract's company.
- **Leavers:** requesters marked as left can no longer sign in to the portal, and deactivated analysts lose access straight away (see Security).
- **Single sign-on groups are off until you set them up** on a provider's **Groups and teams** tab. A provider that belongs to a company only appears on that company's portal, not on the analyst login - set its company to Global if your staff sign in with it.

## Rollback

Safe - this release only adds to the database, so you can go back to 3.4.0.
