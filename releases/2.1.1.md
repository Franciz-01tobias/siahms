## What this release is about

**If you connect a Microsoft 365 or Gmail mailbox and you have kept the same `config.php` since before FreeITSM 1.0.0, or assembled it by hand, please upgrade.** On those installs, connecting the mailbox failed with a fatal error rather than an explanation - and the Gmail side of it would have stayed broken however you patched the Microsoft one. This was reported by a user running 1.9.0 who tracked it down himself, and it is the third appearance of the same underlying mistake, so this release also closes the shape of it rather than just this instance.

Everything else here is the tail end of 2.1.0: the ticket list now names the person who raised each ticket rather than the mailbox it arrived at, and the search panel behaves the way people expected it to.

Nothing asks anything of you beyond running Database Verification, and rollback is safe.

## Improvements

- **The ticket list can name whoever you prefer.** A new **Name beside the ticket number** setting under **Tickets → Settings → Row display** offers three choices: **Who raised it** (the new default), **Who replied last** (how it used to behave, for desks that read the queue like a mailbox) and **Hidden**. Each analyst can set their own, and the preview on that tab shows two different names so you can see the difference rather than guess at it.

- **Escape closes the search panel, and you can choose whether clicking away closes it too.** Asked for in [#144](https://github.com/edmozley/freeitsm/issues/144). Escape always works. Click-away is **off by default** and lives in **System → Preferences → Display**, per analyst, because which one you want is a working style rather than a property of the desk. Clicking the ticket you just found, or its properties, keeps the panel open, so acting on a search result does not throw the search away. It applies to Tickets, Change Management, Problem Management and Contracts.

- **The SSL debug tool now answers the question that matters.** **System → Debug tools → SSL / HTTPS verification check** reported a healthy install to the user above while the fatal error was happening on the same machine, because it was checking something that could never come back negative. It now tells you whether your own `config.php` still contains the block the application expects, prints the lines to add when it does not, and stops showing an unqualified tick when it has found something its live tests cannot reach.

## Fixes

- **Connecting a Microsoft 365 or Gmail mailbox could fail with a fatal error.** It affected installs whose `config.php` predates 1.0.0 or was put together by hand - that file is yours and an upgrade never rewrites it, so it can be missing lines the application has since come to expect. Both mailbox sign-in pages now stand on their own. If you applied a fix for this yourself by editing a file under `includes/`, this release makes that edit unnecessary, and your edit would have been overwritten by any upgrade in any case.

- **Outbound HTTPS could fail to verify certificates on those same installs**, reporting *unable to get local issuer certificate* against every service - mail, AI providers, webhooks, sign-in. FreeITSM ships a certificate bundle and now finds it by itself instead of relying on your `config.php` to point at it. If you do name your own bundle, yours is still the one used.

- **The SSL check warned that certificate verification would likely fail when it was working.** On Windows, where FreeITSM uses the certificate bundle it ships with, **System → Debug tools → SSL / HTTPS verification check** printed the bundle's path and then said it could not find one. Nothing was wrong with the verification itself, only with the sentence describing it.

- **A ticket row named your own mailbox instead of the customer** ([#143](https://github.com/edmozley/freeitsm/issues/143)). Where a ticket arrived by email, the list showed the service desk address it came in to rather than the person who sent it - on 52 of 118 rows in my own test data.

- **The War Room was missing from the landing page**, the screen that lists every module as an icon, so the only way in was a link you already knew.

## Upgrading

1. Pull the new code, or rebuild the Docker image.
2. Sign in as an administrator and run **System → Database Verification**.
3. Hard-refresh your browser (Ctrl-F5) - this release updates cached JavaScript.

If you edited any file under `includes/` to work around the mailbox error, take your edit out and let the shipped file stand; it is no longer needed.

## Rollback

Safe - nothing was removed from the database, so you can go back to 2.1.0.
